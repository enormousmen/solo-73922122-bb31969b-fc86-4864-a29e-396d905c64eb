# 单卷恢复控制台(volume-recovery)

虚拟机数据盘尚未恢复完,值班员需要立刻恢复业务读写。本服务提供单卷恢复页:

- **4 KiB 块读写**:本地块用 SQLite 持久化(`<DATA_DIR>/volume.db`);本地缺块时从**内置只读备份镜像**读透;
- **后台回填**:网页一键启动,后台线程把缺块从备份拷贝到本地,页面实时显示进度;
- **按块挂起/放行**:网页可挂起指定块的后台备份读取;挂起期间同一块的**整块写入照常提交**,
  迟到的备份数据(`INSERT OR IGNORE` + 落盘前复查挂起表)**不会覆盖**已提交的业务写入;
  放行一个已被跳过的缺块后,后台会**回头补齐**它;
- **重启续传**:已落盘的块与选块游标都保存在 SQLite 中,进程重启后从**已落盘的进度**继续;
- **断开保护**:只要还有缺块(包括挂起未放行的缺块)就**拒绝断开备份**(HTTP 409);
  只剩挂起缺块时后台保持运行、继续等放行,全部补齐后才允许断开。

## 本版本的选块改进

旧实现对每个缺块都要把全卷已落盘块与挂起块读进内存、再逐块判断,卷越大越慢。
本版本改为:

1. **区间表 `segments`**:已占用块(present ∪ suspended)在 SQLite 中存为合并后的连续区间
   `[start, end)`,连续整段只占一行;空卷时**零行**,启动**不为每块建任务或记录**。
2. **整段跳过**:选块时只需一次主键索引查询,若游标落在某个区间里就**整段跳到区间末尾**,
   不逐块检查本地块或挂起块;随后取该段之后的第一个空洞。复杂度按**区间数**增长,而非块数。
3. **持久化选块游标 `backfill_cursor`**:每落盘一块就把游标推进到该块之后并提交;
   重启后 `maybe_resume` 从游标处续填,不回扫已落盘的块。
4. **放行回头补齐**:放行一个缺块时把它从区间中拆出,并把游标回拨到该块;
   提交回填结果时若发现游标已被回拨,不会把游标又推回去,从而保证该块会被再次派发。
5. **业务写入优先**:整块写入成功后该块立即进入占用区间,之后**不再派给后台**回填。
6. **失败回滚**:写入、挂起、放行、回填落盘都在**单个事务**内同时更新块表、区间表、游标与计数;
   任何一步抛错都整体回滚,选块看到的仍是操作前的状态。
7. **重置隔离**:`reset` 先递增世代并停掉旧 worker,旧的在途选块结果无法落进新卷;
   同时清空区间、游标与计数。
8. **兼容旧卷**:旧版 SQLite 卷没有 `segments` 表,首次启动做**一次顺序扫描**(流式归并
   `blocks`/`suspended`,不载入全量状态)构建区间,并把游标定位到第一个真正的空洞;
   之后正常从进度续填。`meta.segment_version` 记录已完成升级。
9. **页面分段加载**:`GET /api/blocks?start=&count=` 只返回**当前段**的块状态(默认 256 块,
   上限 1024),页面支持「上一段/下一段」和**按块号跳转**;`/api/status` 只返回聚合计数,
   不把全卷块状态载入内存或页面。

```

  app.py               # Flask 服务:存储层(Volume)+ 回填 worker + REST API + 页面

  templates/index.html # 单页控制台:状态卡、分段块网格、按块号跳转、块操作、一键演示

  test_recovery.py       # 原有 7 项:读写/回填/挂起放行/断开/重启/校验

```

## 运行

### Docker Compose(交付方式)

```bash
docker compose up --build
# 打开 http://localhost:8080
```

- `app/Dockerfile` 在构建期生成只读备份镜像 `/app/backup.img`(默认 256 块 × 4 KiB = 1 MiB);
- 本地块、挂起表、区间、游标存于命名卷 `recovery-data` 中的 SQLite;
  `docker compose restart` 后保留,并自动从游标续传;
- 需要更大卷时改 `app/Dockerfile` 的 `BLOCK_COUNT`/`BLOCK_SIZE` 与 compose 环境变量即可
  (备份镜像大小需与之一致)。

### 本地直跑(开发/自测)

```bash
pip install -r app/requirements.txt
python3 app/app.py          # http://localhost:5000
```

可用环境变量:`BLOCK_SIZE`(默认 4096)、`BLOCK_COUNT`(默认 256)、`BACKFILL_DELAY`(默认 0.05s/块)、
`DATA_DIR`、`BACKUP_IMAGE`、`PORT`。

## 网页演示

页面顶部为状态卡与进度条;中部为**分段**块网格(灰=缺失,绿=本地·回填,蓝=本地·业务写入,
黄=已挂起),可用「上一段/下一段」或输入块号跳转;点击块可读取/整块写入/挂起/放行。
底部为**一键演示脚本**,依次执行并打印日志:

1. 重置卷 →
2. 挂起连续块 7、8 →
3. 启动回填 → 回填**整段跳过**挂起段,游标继续推进(日志显示游标与累计跳段数)→
4. 其余块补齐,只剩挂起缺块时后台**仍在运行、等放行** →
5. 挂起期间读块 7 被拒(409)→
6. 挂起期间对块 7 整块写入成功 →
7. 仍有挂起缺块时断开备份被拒(409)→
8. 放行块 8(游标回拨),后台**回头补齐** →
9. 块 7 仍是业务数据(迟到备份数据未覆盖)、块 8 来源为回填 →
10. 补齐后断开备份 → 11. 断开后读/改写块 3 均正常。

**重启持久化演示**:回填进行中执行 `docker compose restart`,刷新页面可见已落盘块保留、
回填自动从游标继续(`GET /api/status` 的 `resumed_on_boot=true`、`backfill_cursor` 为停止时的进度)。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 聚合状态:总块数/已落盘/缺失/进度/回填与备份状态/游标/区间行数/统计 |
| GET | `/api/blocks?start=&count=` | **当前段**块状态(默认 256 块,上限 1024);不返回全卷 |
| GET | `/api/block/<i>` | 读块:本地命中 / 缺块读透备份 / 挂起 409 / 断开且缺失 410 |
| POST | `/api/block/<i>/write` | 整块写入(`{"data": "..."}`,UTF-8 ≤ 4096 B,补 0 凑整块) |
| POST | `/api/block/<i>/suspend` · `/resume` | 挂起 / 放行该块的后台备份读取(放行会触发回头补齐) |
| POST | `/api/backfill/start` | 启动后台回填(已断开备份则 409) |
| POST | `/api/disconnect` | 断开备份:尚有缺块(含挂起未放行)则 409,全补齐才成功 |
| POST | `/api/reset` | 清空本地卷,重置区间/游标(演示用) |

## 关键设计

- **迟到备份数据不覆盖业务写入**:回填落盘用 `INSERT OR IGNORE`;从备份取数到落盘之间的窗口内
  若业务写入已提交,回填结果被丢弃(统计 `late_ignored`);落盘前还会复查挂起表,取数后被挂起的块直接丢弃。
- **挂起语义**:挂起只影响*后台*备份读取——回填选块把挂起块与已落盘块一起整段跳过;
  缺块且被挂起时业务读返回 409;整块写入不受挂起影响,永远可提交。
- **持久化**:块、挂起表、区间、选块游标、回填运行标志、断开标志全部在 SQLite(WAL);重启按标志自动续传。
- **断开条件**:`missing > 0` 时断开返回 409;断开后关闭备份 fd,读写在纯本地完成。
- **计数**:已落盘块数随写入/回填在**同一事务**内维护(`meta.present_count`),
  避免每轮回填/状态查询做全表 `COUNT`。

## 自测情况(已执行)

环境:Python 3.11.2 + Flask 3.1.3 + pytest 9.2.0。

- **pytest 19 项全部通过**(`python3 -m pytest tests/ -v`,约 16–22 s):
  - 原有:缺块读透且不落盘、回填完成、挂起期间读拒/写可提交/放行后业务数据不被覆盖、
    缺块拒绝断开+补齐后断开、跨重启保留并续传、写入校验、并发业务写入不被覆盖。
  - 新增:连续挂起/已落盘块整段跳过且选块 SQL 常数级;空卷零行区间、不为每块建记录;
    分段接口只返回当前段;放行被跳过的块后回头补齐;只剩挂起缺块时后台继续等放行且断开被拒;
    业务写入块不再派给后台(回填读取数 = 总块数−已写块);写入/挂起/放行失败整体回滚;
    重置卷后旧在途选块结果不落新卷;重启从持久化游标续填且不重读已落盘块;
    旧 SQLite 卷(无 segments 表)升级后从空洞续填;取数窗口内放行不被游标覆盖;
    已落盘计数在写入/回填/重置后保持精确。
- **200k 块量级微基准**:单次选块约 0.026 ms、`/api/status` 约 0.08 ms(旧实现全表载入约 330 ms/次)。
- **真实 HTTP 冒烟**(独立进程 + curl/Python,4096 块卷):挂起连续块→回填越过它们→
  只剩挂起缺块时断开被拒→业务写挂起块→放行→回头补齐→断开成功,结果符合预期。
  (`segment_hops=1`,回填读取数=4095,业务块 1 块未被回填。)
- **真实进程重启**:用子进程启动服务,回填到 120/512 块时退出进程,重启后实测
  `resumed_on_boot=true`、游标从 120 附近继续、业务块内容保留、只回填剩余缺块(不重读已落盘块),
  最终补齐并断开成功。
- **页面脚本**:`node --check` 校验内联 JavaScript 语法通过;页面与 API 由 HTTP 冒烟覆盖。
- **compose / 镜像**:本环境**无 Docker**,未实际 `docker compose up`/构建镜像;
  已用 PyYAML 校验 `docker-compose.yml` 结构,并在等价环境(同一 Dockerfile 的
  `python backup_util.py ... 256 4096` + `chmod 0444` + 相同环境变量)下启动服务跑通演示流程。
